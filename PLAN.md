# План: Мипо 2 — минимальный рабочий прототип

> Этот файл — задание для Claude Code. Положи его в корень репозитория `my-personal-ai` и скажи:
> «Выполни PLAN.md по фазам. После каждой фазы — тесты зелёные, коммит, короткий отчёт мне».

## 0. Как работать с этим планом (для Claude Code)

- Делай строго по фазам (раздел 12). Не начинай следующую, пока у текущей не выполнены критерии приёмки.
- Не добавляй ничего сверх плана: никаких новых абстракций, фреймворков, «на будущее». Если чего-то не хватает — спроси.
- Старый код лежит в `TRASH/` только как источник кусков. Не импортируй из `TRASH/` — копируй нужное и упрощай.
- Комментарии, docstring, тексты интерфейса и промпты — на русском, как в старом коде.
- Каждая папка пакета начинается с короткого `README.md` (3–10 строк): что здесь лежит и за что отвечает.
- Файл длиннее ~300 строк — повод разделить. Функция длиннее ~60 строк — тоже.
- Работает на Windows и Linux. Пути только через `pathlib`. Никакого bubblewrap и прочего Linux-only.

## 1. Цель

Мипо — личный локальный ассистент одного пользователя (QA-инженера). Пользователь даёт задачу текстом —
агент выполняет её сам: читает и пишет файлы проекта, запускает скиллы, команды и браузер.
Если для задачи нет инструмента — агент сам предлагает новый скилл (описание, код, библиотеки),
после «да» создаёт его и выполняет задачу. Всё, что агент умеет, видно глазами: в интерфейсе и папками на диске.

Типовые задачи: тест-кейсы по большой документации, ревью тест-кейсов (в том числе больших объёмов),
автотесты (pytest + Playwright), прохождение сценариев в браузере, перевод PDF/DOCX в Markdown,
написание кода и скриптов, поиск информации в браузере.

## 4. Ядро: цикл агента (`agent/loop.py`)

Без LangGraph. Схема хода:

```
собрать контекст (промпт + память + история, сжать под окно)
раунд = 0
пока раунд < лимит (40):
    ответ = модель(контекст, схемы инструментов)        # стрим текста в UI
    если ответ пустой/зациклился → guards.retry (повтор, потом без инструментов)
    если в ответе есть вызовы инструментов:
        для каждого вызова (не больше 4 за раунд):
            проверить аргументы по схеме → ошибка уходит модели, не пользователю
            если инструмент меняет что-то и нет доверия в сессии → карточка, ждать решения
            выполнить → результат в контекст и в историю
        раунд += 1; продолжить
    иначе (ответ текстом):
        прогнать guards (language, promise, plan): если guard вернул подсказку → добавить и продолжить
        сохранить ответ → конец хода
лимит исчерпан → карточка «продолжить ещё 40 или остановить»; «остановить» → последний запрос без инструментов: итог
```

- Подтверждение: ход ждёт решения (`asyncio.Future`) при открытом потоке событий. Ожидание пишется в JSON сессии,
  чтобы карточка пережила перезагрузку страницы. Если перезапустился сервер — ожидание сбрасывается, в чате
  появляется «ход прерван, напишите «продолжай»». Чекпоинтов графа нет.
- Решения по карточке: «да», «нет», «ответить текстом» (текст уходит модели), галочка «разрешать такие до конца сессии».
  Группы доверия: `files_write`, `command`, `skill_run`, `skill_edit`, `browser`.
- Кнопка «Стоп» отменяет ход; уже написанный текст сохраняется с пометкой «(ответ прерван)».
- События в UI (SSE): `delta`, `reasoning`, `tool_call`, `tool_result`, `progress`, `approval`, `log`, `done`, `error`.
- Лог хода (строки под ответом): запрос к модели, раунд, токены, вызовы, срабатывания guards, сжатие контекста.

### 4.1 Guards (`agent/guards/`)

Каждый файл начинается с docstring: что за проблема у маленькой модели, как guard её ловит, сколько раз за ход срабатывает.
Общий интерфейс — одна функция `check(state) -> str | None` (текст подсказки модели или None).
Включение — `data/settings.json` → `guards: {language: true, promise: true, plan: true, retry: true}`, переключатели в Настройках.
Логику брать из `TRASH/src/core/graph.py` (`is_foreign`, `foreign_allowed`, `promises_action`, `plan_nudge`, повтор при `LLMEmptyResponse`/`LLMRepetition`), без изменений по смыслу.

- `language.py` — ответ не по-русски (и пользователь не просил другой язык) → «перепиши по-русски». До 3 раз.
- `promise.py` — ответ кончается обещанием действия без вызова инструмента → «сделай вызовом». До 3 раз.
- `plan.py` — в плане хода остались несделанные пункты → «сделай пункт N». До 4 раз. Вопрос пользователю ход заканчивает.
- `retry.py` — пустой ответ или зацикливание → тот же запрос ещё раз, потом без инструментов, потом ошибка.

### 4.2 Контекст и окно (`agent/context.py`)

- Окно: спросить у сервера модели (перенести `context_length` из `TRASH/src/llm/base.py`), иначе `default_context_tokens` из настроек.
- Состав: системный промпт → память → история сессии → текущий ход.
- Не влезает: сначала самые старые результаты инструментов заменяются строкой
  `[результат read_file docs/a.md убран из контекста — при необходимости прочитай снова]`;
  не помогло — выпадают самые старые сообщения целиком (парами вызов/результат). Модель для сжатия не вызывается.
- Внутри хода то же правило (результаты копятся). Огромную вставку пользователя — в файл проекта, в контекст — края и путь
  (перенести `stash_paste`).
- В UI над полем ввода — «занято ≈N из M токенов».

## 6. Скиллы

### 6.1 Формат папки

```
data/skills/testcase-generate/
├── SKILL.md
└── scripts/
    └── main.py
```

`SKILL.md`:

```markdown
---
name: testcase-generate
description: Пишет ручные тест-кейсы по Markdown-документации. Применять, когда просят тест-кейсы по требованиям или документации.
entry: scripts/main.py
requires: []
secrets: []
timeout: 3600
---
# Что делает
...
# Аргументы (JSON)
- path — файл .md или папка документации в проекте (обязательно)
- limit — сколько страниц за запуск (по умолчанию 20)
# Результат
...
# Примеры
{"path": "docs/auth", "limit": 5}
```

- `name` = имя папки, латиница/цифры/дефис. `description` — одна строка: что делает и когда применять.
- В системный промпт попадает только список `name — description`. Полный `SKILL.md` агент читает через `read_skill`.
- Скиллы только на Python.

### 6.2 Контракт запуска (`skills/runner.py`)

- Команда: `<python из data/skills-env> -I <папка скилла>/<entry>`; рабочая папка — папка проекта.
- stdin — JSON аргументов. stdout — результат (в контекст модели — не больше ~8 тыс. символов; длиннее — целиком в
  `.meepo/skills/<name>/last-output.md`, модели — начало, конец и путь). stderr — строки прогресса, идут в UI событием
  `progress` построчно. Код возврата не 0 — ошибка, модель получает хвост stderr.
- Переменные окружения: `MEEPO_LLM_URL`, `MEEPO_LLM_MODEL`, `MEEPO_LLM_KEY`, `MEEPO_PROJECT`, `MEEPO_SKILL_DIR`,
  `MEEPO_STATE_DIR` (= `<проект>/.meepo/skills/<name>/` — сюда скрипт пишет прогресс для продолжения),
  `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`, `PYTHONPATH` = папка `skills/sdk`, и значения объявленных секретов.
- Таймаут из `SKILL.md`; по таймауту и по «Стоп» убить всё дерево процессов (Windows и Linux).
- Пока скилл идёт, ход ждёт; в UI — строка прогресса и кнопка «Стоп».

### 6.3 Создание и правка скилла

1. Подходящего скилла нет → агент прямо говорит, чего не хватает, и вызывает `create_skill` с: `name`, `reason` (зачем),
   полным `SKILL.md`, файлами `scripts/*`, `requires` (пакеты PyPI с версиями), `secrets` (имена).
2. Карточка показывает всё это одним экраном (код с подсветкой). Решения: «да» / «нет» / «ответить текстом».
3. После «да»: проверка (`name` свободен, `SKILL.md` разбирается, `entry` существует, Python компилируется,
   пакеты — только имена PyPI без ссылок и флагов — перенести проверку из `TRASH/src/connectors/pyenv.py`), установка пакетов
   в `data/skills-env` (uv, если есть, иначе pip), запись папки. Если объявлены секреты без значений — агент просит
   пользователя заполнить их в карточке скилла (раздел «Скиллы» UI) и ждёт.
4. Агент сразу запускает скилл на задаче пользователя (`run_skill`, тоже с подтверждением, если нет доверия).
5. Упал → агент читает ошибку и предлагает `update_skill` с diff — **каждая правка подтверждается заново**.
   После 3 неудачных правок подряд агент останавливается и спрашивает пользователя.
6. `update_skill`: перед записью — копия всей папки в `data/skills/.history/<name>/<дата-время>/`. Откат — кнопкой в UI.

### 6.4 Помощник для скриптов (`skills/sdk/meepo_skill.py`)

Маленький модуль (без зависимостей), чтобы маленькой модели было проще писать скиллы правильно:

- `args() -> dict` — прочитать JSON из stdin;
- `progress(text)` — строка в stderr;
- `ask_llm(system, user, json_schema=None) -> str` — запрос к модели сессии (логику взять из `Model` в `TRASH/src/qa/testcases.py`:
  повторы, `reasoning_effort: none`, срез `<think>`);
- `State(name)` — простой JSON-файл в `MEEPO_STATE_DIR` для продолжения с места остановки;
- `chunks(text, max_chars)` — нарезка по заголовкам (из `testcases.py`).

Правило для всех скиллов (записать в промпт агента и в шаблон `SKILL.md`): **большие объёмы обрабатываются по кускам,
каждый готовый кусок сохраняется в `State`, повторный запуск продолжает с места остановки, в stdout — только итог.**

### 6.5 Стартовые скиллы (`skills/builtin/`)

- `testcase-generate` — режим `generate` из `TRASH/src/qa/testcases.py`: куски, строгая JSON-схема, таблица, проверка стиля,
  `testgen/rules.md` и `testgen/example.json` проекта, продолжение. Убрать привязку к ревизии агента (`MEEPO_AGENT_REVISION`).
  В конце результата — подсказка: «проверь кейсы скиллом testcase-review».
- `testcase-review` — самостоятельное ревью **любого** Markdown-файла с тест-кейсами (не только созданных Мипо):
  аргументы `cases` (файл или папка .md) и необязательный `docs` (документация для сверки). Кейсы режутся пачками,
  каждая пачка — отдельный запрос к модели с чистым контекстом (промпт `REVIEW` из `testcases.py`; без `docs` — только
  качество, стиль, проверяемость, дубли). Результат — файл замечаний рядом + колонка «Вопросы» заполняется, если она есть.
  Продолжение с места остановки.
- `to-markdown` — из `TRASH/src/connectors/library/to_markdown/`, `requires: markitdown[pdf,docx,xlsx,pptx]`.

Скилл автотестов **не** делать — его Мипо должен написать сам (приёмочный сценарий В).

### 6.6 Секреты (`skills/secrets.py`)

- Имена объявлены в `SKILL.md` (`secrets: [JIRA_URL, JIRA_TOKEN]`).
- Значения — `data/secrets/<name>.json`, вне папки скилла (копии в истории и папка скилла секретов не содержат).
- Ввод/изменение — в карточке скилла в UI, поле типа password. В API и модель значения не уходят никогда.

## 7. Браузер (`agent/tools/browser.py`)

Свой небольшой инструмент на Playwright (sync API в потоке или async — на выбор), без MCP.

- Один инструмент `browser` с `action`: `open(url)`, `snapshot()` (текст страницы + список интерактивных элементов
  с ref, ролью, именем и **готовым локатором Playwright** — `get_by_role(...)`/`get_by_label(...)`/CSS),
  `click(ref)`, `type(ref, text)`, `press(key)`, `select(ref, value)`, `screenshot()` (файл в `.meepo/screenshots/`), `close()`.
- Браузер запускается лениво при первом вызове, живёт до конца сессии или `close`. Видимое окно (headed) по умолчанию,
  переключатель в настройках.
- Подтверждение — группа доверия `browser`: первая карточка «разрешить браузер в этой сессии».
- Локаторы из `snapshot` нужны, чтобы агент мог написать автотест по реальной странице.
- Снимок страницы ограничен по размеру; старые снимки в контексте первыми заменяются пометкой (раздел 4.2).
- Установка браузера: `playwright install chromium` — один раз, инструкция в README; если не установлен — понятная ошибка.

## 8. Память (`memory/`)

- Файлы `data/memory/*.md`: `profile.md` (кто пользователь), `preferences.md`, `projects.md`, `solutions.md`
  (успешные решения коротко: «задача → что сработало»), остальное по необходимости. Одна строка — один факт.
- В промпт: `profile.md` и `preferences.md` целиком (с лимитом символов) + до 10 строк из остальных файлов,
  найденных по словам из сообщения пользователя (простой перебор строк, без индекса).
- Автообновление в фоне каждые N сообщений пользователя (настройка, по умолчанию 10): модель читает новые сообщения
  и возвращает операции `add/update/delete` по строкам. Перенести логику из `TRASH/src/memory/service.py`,
  `operations.py`, `validator.py`, убрав SQLite-поиск и QA-опыт как отдельное хранилище.
  Правило в промпте обновления: запоминать личное, коротко — успешные решения, всё, что пользователь просил запомнить;
  не запоминать ход работы, логи, разовые детали.
- `remember` — немедленная запись по прямой просьбе.
- Резюме длинного чата — нет.

## 13. `CLAUDE.md` проекта (создать в фазе 0)

Коротко, чтобы следующие правки не вернули сложность:
- Один агент, простой цикл. Новые возможности — скиллами, не кодом ядра.
- Встроенный инструмент добавляется, только если его нельзя сделать скиллом (нужна живая сессия или доступ к ядру).
- Никаких новых зависимостей, SQLite, MCP, графов, субагентов без явного решения пользователя.
- Заплатка для модели — только новым файлом в `agent/guards/` с описанием и переключателем.
- Всё, что меняет файлы, систему или браузер, — через карточку подтверждения.
- Тексты, комментарии и промпты — по-русски.

## 14. Приёмочные сценарии (руками, LM Studio)
