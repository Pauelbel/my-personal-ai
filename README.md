Локальный LLM-агент с веб-интерфейсом. Работает с моделью, запущенной в LM Studio, хранит разговоры в SQLite и при явном включении умеет читать файлы выбранной рабочей папки. Проект находится на раннем этапе разработки (v0.1).

## Что уже работает

- Сессии с сохраняемой историей: создание, переименование прямо в шапке и удаление с подтверждением.
- Ответы через локальный OpenAI-compatible API LM Studio. Модель выбирается для каждой сессии.
- Чтение списка файлов и небольших UTF-8-файлов внутри рабочей папки сессии. Инструменты выключены по умолчанию; их переключатели общие для всех сессий.
- Светлая и тёмная темы. Ответы агента отображают основные элементы Markdown, включая таблицы и блоки кода.
- Два показателя в шапке: входные токены последнего запроса по данным модели и приблизительный объём всей сохранённой переписки. Пояснения появляются при наведении.

Приложение написано на Python/FastAPI с обычным HTML, CSS и JavaScript. Данные разговоров и настройки инструментов хранятся локально в SQLite.

## Быстрый старт

Нужны Python 3.11 или новее, `uv`, установленный LM Studio и загруженная в нём модель. В LM Studio включите локальный API-сервер; адрес по умолчанию указан в `.env.example`.

1. Создайте локальный файл настроек:

   ```powershell
   Copy-Item .env.example .env
   ```

   В macOS/Linux используйте `cp .env.example .env`. Если адрес LM Studio отличается, измените `LM_STUDIO_BASE_URL` в `.env`. Значение `DEFAULT_MODEL` можно заменить на ID своей модели или оставить модель выбранной в интерфейсе.

2. Установите зависимости и запустите приложение:

   ```powershell
   uv sync
   uv run uvicorn local_agent.main:app --reload --host 127.0.0.1
   ```

3. Откройте [приложение](http://127.0.0.1:8000/) в браузере, создайте сессию и выберите модель под полем сообщения. Описание HTTP API доступно по адресу [127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

Приложение можно открыть без LM Studio, но для ответов модели его локальный API-сервер должен работать. Значение модели в `.env.example` — только пример: оно должно совпадать с моделью, доступной в вашем LM Studio.

## Работа с интерфейсом

- Нажмите Enter, чтобы отправить сообщение; Ctrl+Enter добавляет новую строку. История сохраняется автоматически.
- Нажмите на название сессии в шапке, чтобы переименовать её. Клик вне поля или Enter сохраняет новое название, Escape отменяет правку.
- Провайдер, модель и рабочая папка находятся под полем ввода. Изменения сохраняются автоматически и дополнительно проверяются перед отправкой сообщения.
- Для работы с файлами укажите существующую рабочую папку в сессии и включите нужные пункты в разделе «Инструменты». Модель должна поддерживать вызов инструментов. Без рабочей папки инструменты ей не предлагаются.
- Тема выбирается в Settings и запоминается в браузере.

Первый счётчик в шапке показывает входные токены **последнего запроса** (если LM Studio их сообщила), а не длину последнего ответа. Второй — **приблизительную оценку** токенов во всех сохранённых сообщениях сессии. Это не точный размер текущего окна модели: в запрос включаются только последние `MAX_CONTEXT_MESSAGES` сообщений и системная инструкция. Полная история остаётся в SQLite; сводки диалогов пока не создаются.

## Настройки и данные

Основные переменные перечислены в [.env.example](.env.example): адрес LM Studio, модель по умолчанию, путь к базе, уровень логирования, число сообщений в контексте и таймаут запроса. Локальный `.env` и папка `data/` исключены из Git. По умолчанию база находится в `data/agent.sqlite3`.

Удаление сессии удаляет и её сообщения. Если история важна, сделайте резервную копию базы перед удалением или экспериментами с обновлениями.

## Безопасность и ограничения

- У приложения пока нет учётных записей и аутентификации. Запускайте его на `127.0.0.1`; **не открывайте сервер в интернет** без дополнительной защиты.
- Файловые инструменты умеют только перечислять папки и читать текстовые UTF-8-файлы до 64 КБ. Они принимают относительные пути внутри рабочей папки; запись файлов и выполнение команд не реализованы.
- Глобальное включение инструмента действует во всех сессиях. Не выбирайте рабочую папку с секретами, которые не хотите передавать модели.
- Markdown-рендерер поддерживает распространённую разметку, но пока не всю спецификацию Markdown. Произвольный HTML из ответов не выполняется.

## Разработка и проверки

```powershell
uv sync --extra dev
uv run pytest -q
```

Для отдельной проверки Markdown нужен Node.js: `node tests/test_markdown.mjs`. Проверка с живой моделью обычно пропускается; её можно запустить, задав `LM_STUDIO_TEST_MODEL` и включив локальный сервер LM Studio.
