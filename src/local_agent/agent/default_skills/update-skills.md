# Обновление инструкций

Цель: сохранить полезные правила работы с проектом, чтобы будущие задачи не требовали повторного исследования.

## Когда использовать

- Пользователь просит сохранить вывод, обновить инструкции или говорит «learn!».
- Найдено важное ограничение, повторяющаяся ошибка или проверенный порядок действий.
- Исправление пользователя выявило общее правило работы.

Без явной просьбы сначала коротко предложи пользователю, какую находку стоит сохранить. Не превращай каждую реплику в постоянную инструкцию.

## Порядок работы

1. Сформулируй находку: проблема, установленная причина, правильный подход и когда он применим. Сохраняй только выводы, подтверждённые кодом, результатом инструмента или пользователем. Непроверенные предположения сначала уточни.
2. Через list_files и read_file проверь существующие инструкции выбранного проекта: AGENTS.md, .github/instructions и .agents/skills. При необходимости используй search_files только в связанных папках. Не сканируй весь проект.
3. Выбери место:
   - Короткое правило в 1–4 предложениях — раздел «Выводы» корневого AGENTS.md, если он существует.
   - Если подходящего файла нет — .github/instructions/learnings.instructions.md.
   - Подробная процедура — существующий скилл соответствующей области. Новый скилл создавай только по просьбе пользователя.
4. Прочитай выбранный файл, проверь дубли и противоречия. Обновляй небольшим edit_file с точным old_text; write_file используй для нового файла. Сохраняй чужой текст и ручные правки. Запись выполняется только после штатного подтверждения пользователя.
5. После успешной записи перечитай результат через read_file. Сообщи, какой вывод сохранён, где и почему выбрано это место. При отклонённой или неудачной записи не утверждай, что вывод сохранён.

## Пример

Проверки проекта прошли только после запуска с локальным временным каталогом. Полезная запись: «При проверке этого проекта задавай временный каталог внутри рабочей папки: системный каталог в этой среде недоступен. Используй проверенную в текущей задаче команду».

Если команда не запускалась, не записывай, что она работает. Если причина сбоя не установлена, не превращай догадку в правило.

## Границы

- Все пути должны находиться внутри выбранной рабочей папки. Если нет проекта или нужных инструментов, объясни, чего не хватает.
- Долговременную память обновляет отдельный механизм; не записывай её обычными файловыми инструментами.
- Системный промпт, секреты, личные данные и правила подтверждения записи не меняй.
- Скиллы Meepo хранятся отдельными Markdown-файлами с полями name и description. Не смешивай этот формат с каталогами SKILL.md других агентов.
- Meepo перед каждым сообщением автоматически читает корневой AGENTS.md и .github/instructions/learnings.instructions.md выбранной рабочей папки. Сохранённые там правила подхватываются со следующего сообщения без перезапуска. Другие файлы и вложенные инструкции автоматически не загружаются; их перечитывай инструментом при необходимости. Большие инструкции ограничены бюджетом контекста.
