# Что делает
Читает страницы документации (.md) и по каждой пишет ручные функциональные тест-кейсы одной таблицей:
ID, Название, Приоритет, Предусловия, Тестовые данные, Шаги, Ожидаемый результат, Вопросы.
Большая страница режется на куски по заголовкам; каждый кусок — отдельный запрос к модели со строгой JSON-схемой.
Готовые куски сохраняются, поэтому повторный запуск продолжает с места остановки.
Стиль шагов проверяется автоматически (глагол в начале, длина предложений, канцелярит) — замечания в файле .style.txt.

Правила проекта можно задать в папке проекта:
- testgen/rules.md — что за продукт и правила оформления, дописываются в промпт;
- testgen/example.json — свой пример тест-кейса вместо встроенного.

# Аргументы (JSON)
- path — файл .md или папка документации в проекте (обязательно)
- limit — сколько страниц обработать за запуск (по умолчанию 20)
- force — true: сгенерировать заново, даже если кейсы уже есть (по умолчанию false)

# Результат
Файлы testgen/test_cases/<путь страницы> — тест-кейсы страницы таблицей; рядом .style.txt — замечания по стилю.
В stdout — список готовых файлов и сколько страниц осталось. Дальше кейсы стоит проверить скиллом testcase-review.

# Примеры
{"path": "docs/auth.md"}
{"path": "docs/auth", "limit": 5}
